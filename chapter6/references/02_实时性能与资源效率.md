# 2. 实时性能与资源效率

本系统采用分块处理、双槽缓存与流水重叠，实现 1920×1080 视频的实时矫正。本节从处理延迟与帧率、资源利用率两个方面评价系统性能，综合、布局布线与时序分析使用 PDS2025.2 完成。

## 2.1 处理延迟与帧率

### 2.1.1 处理配置与实时性设计

系统基于紫光同创 PGL50H-FBG484-6 FPGA，实现 1920×1080 视频的镜头畸变与姿态联合矫正。输入 RGB888 视频经过帧自适应 Gamma 处理后，转换为 RGB565 存入 DDR3；矫正模块完成逆投影和重采样，将完整结果写回 DDR3，再转换为 RGB888 输出 HDMI。

| 配置项 | 参数 |
|---|---|
| 输入与输出有效分辨率 | 1920×1080，原生分辨率处理 |
| HDMI 像素时钟与扫描频率 | 148.5 MHz，60 Hz |
| DDR 用户接口与渲染时钟 | 256 bit，100 MHz |
| DDR 像素存储格式 | RGB565，16 bit/pixel |
| 输出分块 | 128×32，双槽缓存 |
| 重采样方式 | 最近邻 |
| 姿态处理范围 | yaw、pitch 各约 ±15° |

为提高处理效率，系统采用以下结构：

- **分块处理与突发预取。** 每个输出块最多包含 4096 个像素，全帧划分为 15×34=510 个块。模块先计算块内源坐标，再将源包围区域以 1～16 beat 突发读入片内缓存，采样阶段以一像素/时钟的启动间隔访问缓存。
- **双槽流水重叠。** 一个块槽执行投影和源区域加载，另一个块槽执行采样与结果写回，减少块间等待。
- **采集与渲染并行。** 两个源帧槽交替使用，使新图像采集与上一帧矫正重叠。
- **完整帧发布。** 两个结果帧槽隔离渲染和显示，最后一笔写事务完成后发布结果，在显示帧边界切换帧槽，保持输出图像完整。

系统由[顶层模块](../src/top/hdmi_ddr3_top.v)连接各处理单元，[帧调度模块](../src/video/pose/fram_buf_pose.v)管理帧槽与数据交接，[分块渲染模块](../src/video/pose/pose_renderer_tiled.v)完成投影、源区域加载和采样写回。

### 2.1.2 帧率目标与时间预算

1080p30 对应每秒处理 30 帧，每帧的时间预算为：

$$
T_{30}=\frac{1}{30}=33.333333\text{ ms}
$$

在 100 MHz 渲染时钟下，单帧预算约为 3,333,333 个时钟周期。每帧包含 2,073,600 个有效像素，目标有效吞吐为：

$$
1920\times1080\times30=62.208\text{ Mpixel/s}
$$

HDMI 采用 2200×1125 总光栅时序，其扫描频率为：

$$
f_{\text{scan}}=\frac{148.5\times10^6}{2200\times1125}=60\text{ Hz}
$$

系统通过 60 Hz HDMI 扫描与约 30 fps 的矫正结果更新相配合，显示端重复读取完整结果帧，形成连续的视频输出。

### 2.1.3 完整链路帧率验证

针对 128×32 分块处理结构，采用完整 1080p RTL 仿真评价帧率。测试同时运行图像采集、预处理、分块矫正和显示，DDR 模型包含 32 拍命令延迟、25% 随机数据停顿以及每 780 拍暂停 35 拍的刷新过程。读写共享 256 bit 数据服务通道，每时钟最多传输一个 beat。

测试输入 28 帧，覆盖 11 种姿态及全部 8 种控制掩码，并检查像素结果、帧身份、帧槽所有权、背压和最终写完成。

| 指标 | 完整链路 RTL 仿真结果 |
|---|---:|
| 稳态有效处理帧率 | 30.000030 fps |
| 最长新结果发布间隔 | 3,333,330 拍，约 33.33330 ms |
| 最慢单帧渲染周期 | 3,314,614 拍 |
| 最慢单帧渲染耗时 | 33.14614 ms |
| 不同源帧的完整结果发布数 | 13 |
| 显示像素比较次数 | 51,840,000 |
| 捕获 FIFO 峰值 | 15/512 个 256 bit 数据字 |
| 日志错误数 | 0 |

有效处理帧率按稳态首末新结果发布时刻计算：

$$
f_{\text{new}}=\frac{(N-1)f_{\text{DDR}}}{C_{\text{last}}-C_{\text{first}}}
$$

其中 N 为完整新结果帧的发布数，C 为 100 MHz 时钟计数。测试统计覆盖启动、稳态和排空阶段，帧率采用稳态发布间隔计算。

相对 30 fps 单帧预算，最慢渲染耗时的余量为：

$$
\triangle T=33.333333-33.14614=0.187193\text{ ms}
$$

时间余量约为单帧预算的 0.56%，该完整链路压力测试达到 1080p30 目标。测试配置与统计结果见[帧率验证记录](../verification/20261022_pc_control_sbit.md)及[完整仿真日志](../verification/pds_pc_control_write_ram_20261022/simulation/result.log)。

工程在 PDS2025.2 中完成综合、布局布线和静态时序分析，快、慢角已分析路径均满足约束。Slow/Fast 最小 setup 余量分别为 +0.721/+0.121 ns，DDR/渲染域 slow setup 余量为 +1.245 ns。异步 FIFO Gray 总线最大 skew 为 1.491 ns，满足 6.734 ns 的约束。结果见[PDS2025 时序记录](../verification/20261024_timing_review.md)、[数值时序报告](../verification/pds_timing_review_20261024/numeric_timing.json)及[FIFO 约束报告](../verification/pds_timing_review_20261024/pose_fifo_cdc.json)。

### 2.1.4 端到端硬件延迟

端到端硬件延迟定义为同一源帧从 FPGA 输入端被接受，到矫正后的对应图像在输出端开始发送有效像素的时间。按照当前完整帧缓存结构，其组成如下：

$$
T_{\text{e2e}}=T_{\text{capture}}+T_{\text{queue}}+T_{\text{render}}+T_{\text{handoff}}+T_{\text{scan,start}}
$$

| 延迟分项 | 起止事件 |
|---|---|
| 图像采集 | 接受输入帧 SOF → 该帧最后有效数据写入 DDR 完成 |
| 调度等待 | 源帧可用 → 矫正模块开始处理 |
| 矫正渲染 | 开始处理 → 最后一笔结果写事务完成 |
| 帧槽交接 | 结果写完成 → 显示端在帧边界完成切换 |
| 输出起始等待 | 完成切换 → 对应结果帧首个有效像素输出 |

完整链路 RTL 仿真中的最慢渲染耗时为 33.14614 ms，作为端到端延迟的渲染分项。板级端到端延迟采用同源帧标记法测量：输入递增帧号或可见跳变块，以逻辑分析仪或统一参考计数器记录输入 SOF 和对应输出 DE，匹配同一源帧后计算时间差。

测量时预热系统后连续采样至少 60 s，记录平均值、P95、最大延迟及样本数，并覆盖零姿态、双轴 ±15° 和功能开关切换。当前板级端到端延迟记录为待测，帧率与延迟分别按各自测量事件统计。

## 2.2 资源利用率

### 2.2.1 PDS2025 综合与布局布线结果

工程目标器件为 PGL50H-FBG484-6，资源数据取自 PDS2025.2 的综合和布局布线报告。综合阶段用量如下：

| 资源 | 综合使用量 | 器件容量 | 利用率 |
|---|---:|---:|---:|
| LUT | 14,565 | 42,800 | 34.03% |
| 寄存器 FF | 15,010 | 64,200 | 23.38% |
| APM（DSP 类算术资源） | 45 | 84 | 53.57% |
| DRM18K 等效容量 | 103 | 134 | 76.87% |
| 分布式 RAM LUT | 594 | 17,000 个可作 RAM 的 LUT | 3.49% |
| 锁存器 | 0 | — | — |

紫光同创工具将硬算术资源记作 APM，本文按该口径评价 DSP 类资源。分布式 RAM LUT 是总 LUT 使用量的子项。

布局布线后的物理资源占用如下：

| 资源 | 最终使用量 | 器件容量 | 利用率 |
|---|---:|---:|---:|
| LUT | 16,897 | 42,800 | 39.48% |
| 寄存器 FF | 14,875 | 64,200 | 23.17% |
| APM | 45 | 84 | 53.57% |
| DRM 物理位置 | 104 | 134 | 77.61% |

综合与物理阶段分别反映逻辑优化和实际映射结果。DRM 由 102 个 DRM18K 与 2 个 DRM9K 组成，折算容量为 103 个 DRM18K，占用 104 个物理位置。最终尚余 30 个 DRM 位置和 39 个 APM，支持后续功能扩展。

原始数据见[PDS2025 综合报告](../verification/pds_timing_review_20261024/prj_tasks/syn_1/synthesize/hdmi_ddr3_top.snr)和[布局布线资源报告](../verification/pds_timing_review_20261024/prj_tasks/pnr_1/place_route/hdmi_ddr3_top.rur)。

### 2.2.2 存储组织与缓存容量

系统将完整帧存放在片外 DDR3，片内保留当前块处理所需的源像素、坐标和输出数据。主要缓存组织如下：

| 缓存 | RTL 组织 | 逻辑数据容量 |
|---|---|---:|
| 双槽源图像缓存 | 2×2048×256 bit | 128 KiB |
| 双槽坐标缓存 | 2×4096×23 bit | 23 KiB |
| 双槽输出块缓存 | 2×256×256 bit | 16 KiB |
| 采集与显示异步 FIFO | 2×512×256 bit | 32 KiB |
| 以上四项合计 | 主要数据缓存 | 199 KiB |

这些容量按 RTL 数据位计算，实际 DRM 占用由宽深配置、端口方式和资源块粒度共同决定。

一幅 1920×1080 RGB565 图像占用 4,147,200 bytes，约 3.955 MiB；RGB888 图像占用 6,220,800 bytes。采用 RGB565 存储后，单帧容量和相同访问次数下的数据载荷减少 33.33%。输出侧通过 RGB565→RGB888 位扩展适配 HDMI 接口。

DDR 中两个源帧槽和两个结果帧槽合计有效像素载荷约 15.82 MiB。每个帧槽的地址间隔为 16 MiB，四槽地址窗口合计 64 MiB；片内缓存按块循环复用。

### 2.2.3 资源优化与性能配合

**分块尺寸优化。** 输出块由 128×64 调整为 128×32，双槽坐标缓存由 46 KiB 降为 23 KiB，双槽输出缓存由 32 KiB 降为 16 KiB，共减少 39 KiB 逻辑存储。两个源缓存槽各保持 2048 个数据字，保留 ±15° 姿态变换所需的源区域容量。

**双槽缓存复用。** 投影、源区域加载与采样写回通过两个块槽交替重叠。完整帧置于 DDR，片内仅保存当前处理窗口，兼顾访问局部性与 RAM 开销。

**共享突发缓冲。** 采集和渲染客户端分别使用 16×256 bit 分布式 RAM 突发缓冲，DDR 仲裁器通过 beat 索引读取数据，减少宽移位寄存器和重复数据暂存。缓冲保持至最后有效写握手完成，支持 DDR 背压与突发事务交接。

**定点计算与小表。** 坐标投影采用定点流水线，三角函数与 Gamma 采用小表或组合逻辑，将计算资源和存储需求集中在当前处理数据上。

采用 128×64 分块的基准设计使用 122/134 个物理 DRM 位置，经过分块尺寸、控制和缓存组织的综合优化后，PDS2025 最终实现使用 104/134，减少 18 个，降幅约 14.75%；物理 DRM 占用率由 91.04% 降至 77.61%。相关结果见[128×64 基准报告](../verification/20261010_pose_tiled_30fps.md)与[PDS2025 实现记录](../verification/20261024_timing_review.md)。

系统以分块缓存、突发访问和流水重叠支撑 1080p30 处理目标，在 PDS2025 实现中将最终 LUT、FF 和 APM 占用分别控制在 39.48%、23.17% 和 53.57%，并为后续扩展保留片内资源空间。
